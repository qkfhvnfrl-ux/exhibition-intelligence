# 3단계 기능 제거·보존 및 검증 경계

확인일: 2026-11-12 (Asia/Seoul). 시작 기준: `aff4f5ca909bfbc7a945a512a2813b9513dfbeb5`.

이 문서는 기존 소스·빌드 구조를 읽어 확정한 제거 경계와 검증 항목이다. 최초 작성 시점에는 새 화면 구현이 진행 중이므로, 아래 항목을 구현/브라우저 검증 완료로 표시하지 않는다. 최종 실행 결과는 3단계 검증 기록에 별도로 남긴다.

## 기존 진입점과 제거 경계

| 기존 기능 | 구현 위치 | v2 처리 |
| --- | --- | --- |
| 현장 사진 등록·수정·삭제·사진 저장소 | `src/field-records.js`, `src/field-records.css`; `src/review.js`의 `#records` | 일반 화면·라우트·런타임 import·배포 파일에서 제외 |
| 업체 메모·사진 주석·검토 상태·확정본 | `src/review.js`, `src/review-state.js`; `#cases`, `#report` 등 | 편집/스냅샷 기능과 저장소 접근을 새 앱에 이식하지 않음 |
| 작업 JSON 백업·복원 | `src/review.js`, `src/review-state.js`, `src/app.js`, `src/field-records.js` | 버튼뿐 아니라 파일 입력·직렬화·복원 처리 의존성을 배포에서 제외 |

| 진행 단계·작업 관리 표시 | `src/review.js`와 `src/review.css`의 `progress-strip`, 작업 상태 편집 | 임원 화면에 이식하지 않음 |
| 사진 확대·추가 각도·비교 | `src/public-gallery.js`, `src/event-reports.js` 등 | 기능을 새 v2 모듈로 구현. 기존 전체 모듈을 런타임 의존성으로 연결하지 않음 |
| 보고용 PDF | `src/event-reports.js`, 기존 print 스타일 | 새 업체/핵심 보고 자료와 인쇄 스타일로 연결; 개인 작업 확정본 기능과 분리 |
| 기존 실사진·출처·연구 데이터 | `assets/`, `data/` | 원본 보존. 검증·이전 규칙에 따라 필요한 데이터를 v2 행사별 파일로 생성 |

기존 `src/review-state.js`는 escape/URL 검사 같은 유틸리티와 메모·백업·확정본 처리를 함께 담고 있다. 새 앱은 이 파일을 import하지 않고 필요한 순수 유틸리티를 v2에 분리한다. 함수 호출을 숨기는 것만으로 불필요한 의존 모듈이 제거된 것으로 간주하지 않는다.

기존 `src/review.js`는 초기화 때 저장소를 읽고 백업 구조를 정리하며, 메모·주석·비교 동작에서 다시 저장한다. 따라서 기존 shell을 감춘 뒤 새 지도만 끼워 넣는 방식도 보존 경계에 적합하지 않다. 새 `index.html`이 v2 진입점만 불러오도록 교체한다.

## 빌드 허용 목록

시작 기준의 `scripts/build.mjs`는 `index.html`, `legacy.html`, 전체 `src`, 전체 `assets`를 복사한다. 최종 빌드는 이 전체 복사를 아래 허용 목록으로 바꾼다.

| 허용 경로 | 조건 |
| --- | --- |
| `index.html` | v2 모듈·스타일만 참조 |
| `src/v2/` | 새 앱의 실제 import/CSS 의존성만 포함. 이전 편집·보관함 모듈 import 없음 |
| `data/v2/app/` | 행사 선택용 인덱스와 필요한 회차별 데이터. 원장·진행률·작업 큐 제외 |
| `assets/`의 실제 사용 가능한 사진/지도/글꼴 등 정적 파일 | 원본 사진 수를 임의로 줄이지 않음. 지도·사진 이용 조건과 원문 출처 유지. 기준 assets는 JPEG 16개·WebP 65개이며 실행 코드 없음 |
| `version.json`, `.nojekyll` | 정상 실행·정적 호스팅 보조 파일 |

`legacy.html`, 기존 `src/*.js`/`src/*.css`, `data/review.json`, `data/review-photos.json`, `data/catalog.json`, `data/event-reports.json`, `data/v2/registry.json`, `data/v2/collection/`, 조사용 문서는 배포하지 않는다. 이 파일들은 연구/이전 원천 또는 복구 자료로 저장소와 이력에 보존한다. 원본 삭제나 관리자 화면 추가는 필요하지 않다.

최종 빌드는 `dist`를 깨끗이 다시 만들고 허용한 파일만 복사해야 한다. 이전 빌드의 `legacy.html`이나 저장소 편집 모듈이 남으면 실패다. 개발 확인도 저장소 루트가 아니라 이 빌드 산출물을 기준으로 한다.

## 브라우저 기록 보존

- localStorage `fieldnote.review.adex2025.v1`
- localStorage `fieldnote.workspace.v1`
- IndexedDB `fieldnote-field-photos-v1`, version 1, object store `photos`

새 앱에서 위 기록을 읽어 축소 저장하거나 삭제하지 않는다. `clear`, `removeItem`, `deleteDatabase`, 기존 DB schema upgrade를 호출하지 않는다. 필요한 지도·검색·선택 상태는 URL과 브라우저 이동 기록으로 유지하며 기존 저장소를 재사용하지 않는다. 보존 검사는 격리한 단위시험의 sentinel 저장소로 수행하고 실제 사용자의 저장소에 시험 데이터를 기록하지 않는다.

단위시험은 다른 회차 ID, 좌표 없는 업체, 공동부스, URL 왕복/손상 값, 저장소 접근 금지, 배포 경계처럼 실제 회귀 위험을 확인한다. DOM에 같은 문구가 있다는 검사만으로 사용자 동작 완료를 주장하지 않는다. 기존 83개 검사는 원본 보존·데이터 기반 검증으로 남길 수 있으나 새 화면 조작의 검증을 대신하지 않는다.

## 시각 검토 기준

간격 4px 기준 → 절제된 중립색/선택 상태색 → 일관된 아이콘 → 짧은 한국어 문구 → 충분한 본문 크기 → 지도 중심 배치 → 포커스/라운드/표 상태 → 실사진 → 짧은 시점 이동 순서로 검토한다. 지도와 실제 사진에 정보량을 배정하고 관리용 요약 숫자·장식 패널을 확대하지 않는다. 한글 본문·캡션을 작은 영문 보조 문구처럼 처리하지 않는다. 입체 모션은 `prefers-reduced-motion`에서 생략하고 정보·선택은 동일하게 유지한다.

## 구현 후 독립 소스·산출물 검토

같은 날짜의 3단계 작업 트리에서 `src/v2/app.js`, `state.js`, `data.js`, `details.js`, `map-view.js`, 빌드 스크립트와 생성된 행사 파일을 재검토했다. 브라우저 조작·실기기·실제 PDF 저장 검증은 이 검토의 범위가 아니며, 루트 작업의 별도 검증 기록을 따른다.

확인한 수정 결과:

- `index.html`은 v2만 불러오고 빌드는 `src/v2` 및 행사별 app 데이터만 복사한다. 기존 편집 모듈·보관함 HTML·원장 JSON은 검토한 `dist`에 없다.
- v2 런타임 import는 v2 폴더 내부에 한정된다. 기존 localStorage 키/IndexedDB 이름 또는 저장소 API 접근 코드가 없다. 실제 사용자 기록을 열어 검사하거나 시험 데이터를 넣지 않았다.
- 지도 도형 32개는 검증된 public 원장의 좌표와 값이 모두 일치한다. 다른 네 행사는 새 좌표를 만들지 않았으며 좌표 없는 업체는 목록으로 연결된다.
- 직접 링크는 행사·검색·분류·구역·시점·2D/입체·업체·사진·비교 선택·둘러보기 순서를 왕복 보존한다. 과거 개인 편집 hash는 v2 탐색으로 처리하며 과거 UI를 다시 열지 않는다.
- 실제 사진 버튼의 ID를 URL에 저장했을 때 뷰어에서 같은 사진·원문·회차 구분으로 찾을 수 있다. 화면의 추가 각도를 잘라 내지 않는다.

독립 검토에서 발견한 연결 오류와 처리:

| 문제 | 수정 확인 |
| --- | --- |
| 카탈로그 anchor의 기본 새 탭 열기와 callback `window.open`이 겹침 | callback이 탐색을 소유할 때만 기본 동작을 막음. callback 없는 링크는 native 탐색 유지 |
| 비교 PDF 버튼이 `comparison:true`를 전달하지 않아 업체별 보고로 출력 | 앱의 비교 인쇄 callback에 `comparison:true` 연결 |
| 원문 조건 필드 `note/evidenceStatus`와 화면의 `limitations/independence`가 달라 출처별 조건이 빠짐 | 두 데이터 형태를 처리하고 단일 근거·재전재·독립 관찰의 범위를 표시 |
| 동일 URL의 오래된 출처 행이 새 검토 출처의 제목·조건을 덮음 | editorial 출처를 우선하고 동일 URL의 조건을 합침. 실제 5개 사례의 원문 조건 13건이 화면·인쇄에 유지됨 |
| 자동 부스 초점 완료 후 navigation flag가 남아 첫 수동 이동 기록을 대체할 수 있음 | 자동 초점 완료 시 flag를 해제하는 소스 확인. 실제 뒤로/앞으로 검증은 브라우저 기록에서 별도 확인 |

추가한 `tests/v2-integration-audit.test.mjs`의 7개 검사는 모두 통과했다. 이어 실행한 `node --test tests/v2-*.test.mjs`는 **60개 통과, 실패/생략 0**이었다. 이는 해당 작업 트리 시점의 결과이며 전체 검사 수나 최종 구현 커밋을 대신하지 않는다.

검토 중 좁은 화면 QA를 위한 임시 HTML이 `dist`에 추가될 수 있다. 허용 목록 검사는 이를 최종 산출물에서 허용하지 않는다. **최종 `npm run build` 후 전체 검사**로 임시 파일이 빠지고 앱 소스와 배포 사본이 일치하는지 다시 확인해야 한다. 이 문서 때문에 임시 QA 페이지를 배포 허용 목록에 추가해서는 안 된다.
