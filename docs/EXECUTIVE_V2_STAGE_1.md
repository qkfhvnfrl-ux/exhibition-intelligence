완성할 제품

상무가 첫 화면에서 실제 전시장 배치도를 둘러보고, 부스를 누르면 그 업체의 현장사진·출품장비·분석을 바로 읽을 수 있는 웹앱입니다.

완성차부터 작은 임무장비·부품까지 차량 체계개발과 조금이라도 관련된 참가기업을 폭넓게 다루고, 핵심 보고에서는 업체별·전시회별 개발 방향과 검토 가치를 간결하게 전달해야 합니다.

최상위 기준

- 지도·사진·분석의 완성도와 정보량을 우선합니다. 기업 수를 임의로 제한하지 마세요.
- 현대로템 차륜형장갑차 체계개발 관점에서 완성차, 동력전달, 차축·현수·조향·제동, 타이어·CTIS, 냉각·공조, 전력·배터리·배선, 소화·방호, 통신·항법·광학·상황인식, 임무컴퓨터, 원격·무인체계, 좌석·내장·지휘소·의무후송 모듈, 커넥터·밸브·펌프·실링, 정비·시험·진단·시뮬레이션·제조기술까지 조사합니다. 기업 규모·인지도·사진 유무로 제외하지 마세요.
- 해당 회차에 관한 자료를 중심으로 구성합니다. 회사 일반제품 소개를 실제 출품품목으로 바꾸지 마세요.
- 주 메뉴는 ‘전시장 탐색 / 업체·장비 / 핵심 보고’ 세 개로 정리합니다. 검색·비교·PDF는 필요한 화면에 붙입니다.
- 개인 사진 등록, 메모·주석 편집, 백업·복원, 과거 보관함, 개발 진행률·디버그 등 보고에 불필요한 기능은 일반 화면과 최종 배포 기능에서 제거합니다. 기존 원본·사용자 기록은 보존하고 브라우저 저장소를 지우지 마세요. 보존을 위해 복잡한 관리자 화면을 새로 만들 필요는 없습니다.
- 출처·자료 기준일·중요한 해석 조건은 유지하되 작고 명확하게 배치합니다. 사실/해석/확인 같은 큰 관리용 패널을 화면마다 반복하지 마세요.
- 실제 제품사진·부스사진·자료를 사용합니다. 형상·성능·전시 여부·부스 위치를 만들어 채우지 마세요.
- 핵심 주장은 원문 근거와 다른 자료를 재대조합니다. 출처가 하나뿐이면 단일 근거로 표시하고 같은 보도자료의 재전재를 독립 검증으로 세지 마세요.

unslop 적용

실제 SKILL.md와 필요한 references를 읽고 사용한 커밋을 기록하세요. 설치 기능이 있으면 설치하고, 없으면 프로젝트의 기존 규칙에 맞는 스킬 경로에 원본을 보관해 적용하세요. 복사·수정 시 원저작자·라이선스 표기를 보존하세요.

간격·색·아이콘·문구·글꼴·배치·세부요소·사진·움직임을 순서대로 다듬되, 한글 가독성·많은 실사진·정확한 수치·의미 있는 상태색을 우선하세요.

이번에 명시적으로 요청한 기능 삭제와 구조 변경을 수행하세요. 디자인 방향은 이 지시로 정했으므로 통상적인 디자인 선택마다 재확인을 요청하지 마세요.

1단계 작업

1. 현재 앱을 확인하고 기준 커밋과 복구 지점을 남긴 뒤 작업 브랜치를 만드세요.
2. 기존 기능·데이터·배포 구조를 조사하고 유지/제거/이전할 항목을 확정하세요.
3. 위 공통 기준과 단계 순서를 docs/EXECUTIVE_V2_BRIEF.md에 저장하세요. 순서는 2단계 공식 원장·지도, 3단계 지도·업체 화면 구현, 4단계 ADEX, 5단계 Eurosatory, 6단계 DSEI, 7단계 IDEX, 8단계 SAHA 조사 확장, 9단계 종합 보고·검증·배포입니다. 아직 받지 않은 상세 지시를 추측해 만들지 마세요. 이후 받은 각 단계 원문은 docs/EXECUTIVE_V2_STAGE_N.md에 저장하고 BRIEF에서 연결해 다른 실행에서도 이어갈 수 있게 하세요.
4. docs/EXECUTIVE_V2_STATUS.json과 docs/EXECUTIVE_V2_HANDOFF.md에 단계별 상태·진행 브랜치·기준 커밋·확인 근거·미완료 작업·정확한 다음 시작점을 기록하세요.
5. 이후 모든 단계는 이 문서를 읽고 실제 소스·데이터를 수정하며, 검증한 묶음마다 저장·커밋하도록 작업 규칙을 만드세요. 실행 여유가 있으면 여러 묶음을 연속 처리하되 한 업체나 자료에 막혀 전체 작업을 멈추지 마세요.
6. 기존 배포를 교체하기 전까지 개발 브랜치와 미리보기에서 확인하세요. 단계 종료 전 코드·데이터·상태 문서를 커밋하고 GitHub 작업 브랜치의 원격 반영을 확인하세요. HANDOFF에는 원격 브랜치와 구현 기준 커밋을, 최종 응답에는 실제 반영 커밋을 기록하세요. 원격 저장이 실패하면 성공했다고 보고하지 말고 복구 가능한 산출물과 미반영 범위를 남기세요.
