## 로컬 초안 3종

검토 진입점: `review/index.html`. 기존 `src/v2`와 실제 데이터·사진을 참고한 독립 초안이다. 제품 빌드 allowlist 밖에 두고, 생성된 원본 앱 JSON 대신 공개 필드만 추린 검토용 데이터를 사용한다.

1. **지도**: 짧은 회차 선택 헤더 → 왼쪽 업체 검색/목록 → 화면 대부분의 공식 지도. 검증된 영역만 클릭 가능. 공동관은 업체 선택을 거치고 위치 미확인 업체도 목록에서 접근한다.
2. **업체 메인**: 지도 복귀·종합보고 → 업체/회차/국가/확인된 홀 → 큰 현장사진 → 장비별 대표사진과 설명. 현대로템·현대위아·기아 3사를 검토 표본으로 삼는다. 현대위아의 별도 부스 전경 미확보는 장비 사진과 구별한다.
3. **종합보고**: 한 문장 메시지 → 실제 사진 3장과 사례 주제 → 이전/이번/대표사례 비교 → 짧은 해석·기준일·한계. 2023 대비 변화가 확인되지 않은 칸은 보류로 표시한다. 모바일은 글자를 축소해 한 화면에 강제 배치하지 않고 세로로 읽는다.

사내 참고 장표는 전달되지 않았고 저장소에도 tracked Office/PDF 파일이 없다. 과거 장표를 확인했다고 가정하지 않는다. 이 초안은 전달 TXT의 배치·설명 원칙만 적용했다. 과거 장표 기준의 세부 개선 비교는 파일 제공 후 가능하다.

| 현재 문제 | 개선안 | 기대효과 | 추가 작업 |
| --- | --- | --- | --- |
| 사진보다 설명/패널이 먼저 보임 | 업체 전면 현장사진 + 장비별 설명 | 현장에서 안내받는 흐름 | 사진 연결 및 보강 |
| 사진마다 맥락·제품이 분산 | 장비별 갤러리·공통 설명 | 중복 감소, 형상 비교 명료 | productIds 및 형상 검수 |
| 보고가 긴 업체목록 | 16:9 요약 + 사례 근거로 이동 | 한 화면 핵심 파악 | 직전 회차 대조·실제 PDF 검증 |

표시 가능은 권리 필터 이후 `src`가 존재한다는 뜻이며 모든 사진의 현재 브라우저 로딩 완료 수가 아니다. 명칭 수는 법인 검증 수·전체 모집단 수가 아니며 제품 수에는 제품군·서비스가 포함된다. 사진 수는 회차별 기록이므로 고유 자산으로 합산하지 않는다.

- ADEX 29개 조사 사례 중 기존 완료 14·자료부족 15, 미착수 명칭 346. 전체 모집단과 야외 명단은 미확보.
- ADEX 지도는 확인 영역 32개·명칭 35개. 나머지 4회차는 검증 좌표 0개. 부스번호만으로 좌표 생성 금지.
- 표본 사진: 현대로템 2장(부스/K2PL), 현대위아 2장(RCWS/105mm), 기아 3장. 기존 7장 `productIds`가 모두 비어 있어 원장 캡션·원문·형상 대조 후 제품 연결 필요.
- 신규 사진 확보 실적은 이번 A단계에서 0장. 기존 자산 활용과 원문 재열람을 신규 확보로 세지 않는다.
- 다음 사진 우선순위: 3사 장비별 추가 각도·현대위아 부스 전경 → 이오시스템/STX 등 임무장비·구성품의 링크 자료 → 한화 계열 실제 회차 근거와 출품 연결. 최종 범위를 3사로 제한하지 않는다.
- 2023 제14회와 2025 제15회 및 격년 개최는 기아 제조사 원문으로 확인했다. 이는 개최이력 근거이며 같은 장비 형상·전략 변화의 검증은 아니다. [2023 원문](https://www.hyundaimotorgroup.com/ko/news/CONT0000000000116922), [2025 원문](https://www.hyundaimotorgroup.com/ko/news/CONT0000000000190141).

## 데이터 흐름과 공개 정리

`collection`은 공식 명단/누락 큐, `research`는 회차별 출품·분석·사진 원천, `maps`는 근거 있는 좌표이다. `compile-v2-data.mjs`가 registry/public을, `compile-v2-app.mjs`가 editorial/research/map-display를 합쳐 `app/events/*.json`을 생성한다. `build.mjs`는 index/src-v2/assets/app shard만 dist로 복사한다. 생성 JSON만 고치지 않는다.

`workConnection`은 컴파일러의 필수 입력이며 공개 편집·분석 29건씩과 관련 주장 29건에 투영된다. 화면 숨김만으로 해결되지 않는다. 원천과 스키마 검증, 문장, 생성기, 테스트, 문서를 함께 정리해야 한다. assets 전체 복사도 재점검해야 한다. dist에 없는 원장·문서도 공개 GitHub 추적 대상이면 공개 자료이다.

현재 이력의 관련 도입 커밋은 `8cc0bcd`, `91dee14`, `546838f`에서 확인했다. 이번에 이력을 수정하지 않았다. 후속 정리는 현재 공개 파일의 수정으로 진행하고, 보존이 필요한 실제 내부 원본은 Git 밖의 지정 보관 위치를 정한 뒤 취급한다. 원본 영구 삭제·이력 재작성은 별도 결정이다. 기존 localStorage 키와 IndexedDB는 접근·변경하지 않는다.

## 기능 유지·변경·공개 화면 정리

- 유지: 5개 회차, 전체 후보와 조사 원장, 검증 지도 좌표, 검색, 출처·이용조건, 사진 확대, 필요한 비교·인쇄, 기존 URL/ID 호환.
- 변경: 업체 전면 화면, 장비 설명·사진 연결, 지도 복귀 상태, 종합보고, 공개용 데이터 계약.
- 정리: 내부 업무 관련 내용, 중복 메뉴/탐방 안내 등 불필요한 요소. 기존 기울임 지도는 기본 2D로 단순화 제안; 실제 3D 도입 없음.
- 이미 제외됨: 개인 사진 업로드·메모·백업/복원·보관함은 v2 배포에서 빠져 있다. 이번에 새로 제거한 것으로 집계하지 않는다. 원본·사용자 기록은 보존한다.

## 필요한 결정

1. 권장안: 큰 지도 → 별도 업체 메인 → 장비 세로 설명 → 16:9 종합보고(모바일 세로 읽기). 대안: 지도 옆 업체 패널을 유지하되 확장한다. 장비 설명 밀도와 현장감에는 권장안이 적합하다.
2. 권장 공개 범위: 검증된 결과를 기존 `/preview/`에 먼저 반영하고 루트 1.1.0은 유지. 대안: 최종 검토 후 루트까지 함께 교체. 공개 반영은 아직 승인되지 않았다.

이미 확정된 조사 범위·실사진 중심·내부 내용 배제 자체를 재승인받는 질문이 아니다. 사용자 AGENTS의 구현 전 승인 및 전달 프롬프트 A단계 선검토/C항 공개 승인 경계에 따른 결정이다.

## 검증과 남은 문제

- 기존 build 성공. check 152개 중 150 통과·2 실패. 실패는 Windows symlink 생성 권한과 경로 구분자 이식성 문제로 재현. [자세한 증거](evidence/REDESIGN_BASELINE_CHECKS.md).
- lint 스크립트 없음. 테스트를 완전 통과로 보고하지 않는다.
- 공개 화면에서 회차 전환·지도→현대로템·사진 2장 로딩·기존 보고를 확인. 지도 배경은 브라우저에서 로딩 지연 관찰, 공식 PNG HEAD는 200 image/png 328639bytes. 접근 경로별 결과를 구분한다.
- 감사 집계와 출처/권리 재확인: [데이터 증거](evidence/REDESIGN_AUDIT_DATA.json).
- 3종 로컬 초안 검증 결과와 스크린샷은 EVIDENCE.md에 기록한다.
- 실제 휴대폰·저장 PDF·전체 장비별 원문 재검증·5개 행사 전수조사·공개 내부 내용 정리·공개 배포는 미완료.
