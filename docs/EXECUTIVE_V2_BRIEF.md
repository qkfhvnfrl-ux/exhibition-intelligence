출처·자료 기준일·중요한 해석 조건은 작고 명확하게 유지합니다. 사실/해석/확인 같은 큰 관리 패널은 반복하지 않습니다. 실제 제품·부스 사진과 자료를 사용하고 형상·성능·전시 여부·부스 위치를 만들지 않습니다. 사진이 없다는 이유로 업체를 빼거나 생성 이미지로 대체하지 않습니다.

핵심 주장은 원문과 다른 자료를 재대조합니다. 하나뿐인 근거는 단일 근거로 표시합니다. 같은 보도자료의 재전재는 독립 검증으로 세지 않습니다. 기존 데이터의 URL 수나 기존 자동검사 통과를 내용의 독립 검증으로 간주하지 않습니다.

## unslop 적용

[고정 버전·원문·적용 기록](EXECUTIVE_V2_UNSLOP.md)을 읽습니다. 순서는 **간격 → 색 → 아이콘 → 문구 → 글꼴 → 배치 → 세부요소 → 사진 → 움직임**입니다. 한글 가독성·많은 실사진·정확한 수치·의미 있는 상태색을 우선합니다. 사용자가 삭제와 구조 변경을 명시했으므로 원본 스킬의 일반적인 기능/섹션 보존 원칙으로 이를 막지 않습니다. 디자인 방향 재승인은 필요하지 않습니다.

## 실행 원칙

실제 소스·데이터를 수정하고 검증한 묶음마다 저장·커밋합니다. 작업 여유가 있으면 여러 묶음을 이어서 수행하고 한 업체나 자료의 막힘은 별도로 기록합니다. 기존 배포 교체 전에는 개발 브랜치·미리보기에서 검증합니다. 단계 종료 전에 코드·데이터·상태 문서를 커밋하고 GitHub 원격 반영을 재확인합니다. 원격 실패 시 미반영 범위와 복구 산출물을 남깁니다. 상세 작업 규칙은 [AGENTS.md](../AGENTS.md)입니다.

1단계에서는 조사·보존·작업 기반과 배포 가드를 완료합니다. 삭제 대상과 3개 메뉴는 확정했으며 화면·기능 제거의 실제 구현은 3단계 작업입니다. 1단계 완료를 v2 UI·전수 조사·배포 완료로 표현하지 않습니다.

2단계 산출물은 [공식 자료 확보 범위](EXECUTIVE_V2_STAGE_2_COLLECTION.md), [공통 데이터 구조·이전 규칙](EXECUTIVE_V2_DATA_CONTRACT.md), [검증 기록](EXECUTIVE_V2_STAGE_2_VERIFICATION.md)에 연결합니다. 원천은 `data/v2/collection`, 지도는 `data/v2/maps`, 기존 ID 이전표는 `data/v2/legacy-mapping.json`입니다. `npm run compile:v2`로 전체 조사용 registry와 화면용 public 데이터를 재생성합니다. 전체 모집단 확보·심층분석은 완료하지 않았으며 남은 범위는 원장 `queues`의 4~8단계로 연결됩니다. 3단계 시작 시 이 파일들과 최신 STATUS/HANDOFF를 함께 읽습니다.

3단계 구현은 [화면 데이터](EXECUTIVE_V2_STAGE_3_DATA.md), [디자인 적용](EXECUTIVE_V2_STAGE_3_DESIGN.md), [기능 제거](EXECUTIVE_V2_STAGE_3_REMOVAL.md), [검증과 한계](EXECUTIVE_V2_STAGE_3_VERIFICATION.md)에 연결합니다. 실제 화면 입력은 `data/v2/app/index.json`과 `events/{eventId}.json`이며 `npm run build`로 생성합니다. ADEX 5개 상세 사례는 전체 모집단 완료와 구별합니다. 실제 PDF 저장·물리적 휴대폰 검증을 남긴 상태로 다음 4단계의 조사 지시를 이어받습니다.

4~8단계 공통 조사 절차는 [EXHIBITION_RESEARCH_PROTOCOL.md](EXHIBITION_RESEARCH_PROTOCOL.md)입니다. 각 회차를 시작할 때 원장·STATUS·HANDOFF와 함께 읽고 동일한 근거·집계·묶음 검증 기준을 적용합니다. 4단계는 3단계 업체 화면을 재사용하며 전체 모집단과 이번 묶음 완료를 구별합니다.

2026-11-12 사용자가 중간 작업본의 고정 링크를 요청했습니다. 별도 진행 확인용 배포와 동일 주소 유지는 [EXECUTIVE_V2_PREVIEW.md](EXECUTIVE_V2_PREVIEW.md)를 따릅니다. 검증한 묶음을 같은 Site에 갱신하며, 구현 원본과 main/기존 공개 사이트의 9단계 전 유지 원칙은 보존합니다. 배포 성공 여부는 STATUS의 실제 결과를 기준으로 합니다.
